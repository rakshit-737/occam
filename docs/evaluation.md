# Evaluation

Every number on this page is generated by a script in `scripts/` from pinned,
checksummed public data and included verbatim from
[`results/`](https://github.com/rakshit-737/occam/tree/main/results). Commands,
runtimes and expected numbers are on [Reproduce](reproduce.md). Intervals are
95%: group-cluster bootstrap where incidents share a group, Wilson score
intervals for small proportions, and fold SD or document bootstrap for
extraction.

**Summary.** OCCAM's ACH does not beat a sensible baseline everywhere, and the
tables below say where it does not. Resistance to *planted spoofable markers*
comes from typing evidence as spoofable: any baseline that simply ignores
spoofable rows is never framed either, and a consistency gate detects more
frames than ACH. What ACH adds is resistance to **mimicry**, where the
adversary copies the framed group's rare techniques and tools as ordinary
hard evidence, and the ability to **decline** when the true actor is
untracked. The price is closed-world accuracy and an 18.6% false-alarm rate
when the markers are genuine.

## 1. False flags: baselines, controls and ablations

Methodology: the 274 leave-one-report-out incidents of section 2, in five
settings: closed, open, *false_flag* (3 spoofable markers frame a random other
group), *authentic* (the same markers point at the true group: a control for
false alarms) and *mimicry* (the framed group's 3 rarest techniques/software
are added as hard evidence). Baselines include the shipped marker-trusting
similarity (marker boost 0.15), a sweep of the boost, similarity that ignores
spoofable rows, IDF coverage, an abstaining similarity and a consistency gate
whose thresholds are cross-fitted over a 2-fold group split. Each ACH
mechanism is removed one at a time.

## 2. Attribution on held-out ATT&CK group usage

Methodology ([ADR 0004](adr/0004-leave-one-report-out-evaluation.md)): every
(group, cited report) pair with at least 4 techniques/software becomes an
incident (at most 3 per group); items supported only by that report are
removed from the group's profile first. *closed*: the true group is a
candidate; *open*: it is removed and the right answer is to decline;
*false_flag*: 3 spoofable markers frame a random other group.

## 3. Extended protocols: all reports, campaigns, unattributed, temporal

Methodology: `loro-all` drops the per-group cap (575 incidents);
`campaigns` holds out ATT&CK campaign objects with all their references;
`unattributed` asks for a decline on campaigns ATT&CK does not attribute
(`unattributed-clean` drops those whose description names a tracked group);
`temporal-X` builds profiles from an older ATT&CK release and attributes
activity that was added to ATT&CK after it, with renamed technique ids
mapped back to the old release.

## 4. Reproduction of published TTP extraction results (rcATT)

Methodology: rcATT's own data (1,490 reports), label filter, 5-fold split and
metrics (Legoy et al., 2020, arXiv:2004.14322), run with the released pipeline,
the pipeline as described in the paper, and OCCAM's classifier family on the
same folds.

## 5. TTP extraction on TRAM2

Methodology: 151 CTI reports, 5-fold cross-validation grouped by document;
classifier thresholds tuned on an inner 20% document split.

--8<-- "results/extraction.md:3:400"

## 6. Campaign clustering

Methodology: per-report slices of ATT&CK group activity plus attributed
campaigns; hyper-parameters chosen on dev groups (even ATT&CK numbers) and
reported on disjoint test groups. Capability only (ATT&CK has no
infrastructure).

--8<-- "results/clustering.md:3:400"

## 7. End-to-end on APTnotes reports

Methodology: public APT report PDFs whose file name names one ATT&CK group;
text extracted, techniques/software found by the span-anchored extractor, then
attributed against all 176 group profiles. The *leak-controlled* rows first
hold out ATT&CK citations of the true group that appear to be the same report.
